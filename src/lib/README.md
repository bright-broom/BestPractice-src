# ライブラリ設計ガイド

## ディレクトリ構造
```
lib/
├── api/            # API通信関連
├── design-system/  # デザインシステム
├── prisma/         # Prismaクライアント
├── store/          # 状態管理
└── utils/          # ユーティリティ関数
```

## 設計原則
1. **モジュール化**
   - 各機能を独立したモジュールとして実装
   - 明確なインターフェースと型定義
   - テスト可能な設計

2. **API通信**
   - APIルートは`lib/api`に配置
   - エンドポイントごとにファイルを分割
   - エラーハンドリングを統一

3. **デザインシステム**
   - 共通のスタイルとコンポーネントを提供
   - カスタムテーマの定義と管理
   - 再利用可能なスタイルユーティリティ

4. **Prismaクライアント**
   - データベース接続とクエリの管理
   - スキーマ定義とマイグレーション
   - 型安全なデータ操作

5. **状態管理**
   - 集中的な状態管理
   - 型安全な実装
   - テスト容易性の確保

6. **ユーティリティ関数**
   - 汎用的な関数を提供
   - 再利用性とテスト可能性を重視
   - 共通のロジックを集約

## 実装ガイドライン
1. **API通信**
   - AxiosやFetchを使用
   - 共通のエラーハンドリング
   - 型定義を明示

2. **デザインシステム**
   - Tailwind CSSをベースにカスタムテーマを構築
   - 共通のスタイルユーティリティを提供
   - コンポーネントのスタイルバリアントを管理

3. **Prismaクライアント**
   - Prismaスキーマの定義
   - 型安全なクエリの実装
   - マイグレーションの管理

4. **状態管理**
   - ZustandやReduxを使用
   - 型安全なアクションとリデューサー
   - セレクタとミドルウェアの活用

5. **ユーティリティ関数**
   - 汎用的な関数を提供
   - 再利用性とテスト可能性を重視
   - 共通のロジックを集約
