# プロジェクト構造設計ガイド

## 基本方針

このプロジェクトは、`src`ディレクトリを基準とした明確な責務分離と一貫性のある構造を採用しています。この設計により、コードの保守性、可読性、スケーラビリティが向上し、チーム開発の効率化を実現します。

## ディレクトリ構造

```
src/
├── app/                    # Next.js App Router
│   ├── layout.tsx         # ルートレイアウト (メタデータ、プロバイダー)
│   └── page.tsx           # ルートページ
├── components/            # コンポーネント
│   ├── forms/            # フォーム関連
│   ├── layouts/          # レイアウト
│   ├── sections/         # ページセクション
│   └── ui/               # 汎用UIコンポーネント
├── hooks/                # カスタムフック
├── lib/                  # ユーティリティと機能
│   ├── api/             # APIルート
│   ├── design-system/   # デザインシステム
│   ├── prisma/          # Prismaクライアント
│   └── store/           # 状態管理
├── styles/              # グローバルスタイル
├── test/                # テストユーティリティ
└── types/               # 型定義
```

## 設計原則

### 1. srcディレクトリ中心主義

- すべてのソースコードは`src`ディレクトリ配下に配置
- 明確な責務に基づいたディレクトリ構造
- 一貫性のある命名規則とファイル構成

### 2. コンポーネントの階層化

```
components/
├── forms/      # フォーム特化コンポーネント
├── layouts/    # ページレイアウト
├── sections/   # 特定のページセクション
└── ui/         # 再利用可能なUI要素
```

- 各ディレクトリは明確な責務を持つ
- コンポーネントの再利用性と保守性を重視
- README.mdによるドキュメント化を推奨

### 3. 機能の分離とモジュール化

```
lib/
├── api/            # APIエンドポイント
├── design-system/  # デザインシステム
├── prisma/         # データベース
└── store/          # 状態管理
```

- 機能ごとに独立したモジュールとして実装
- 明確なインターフェースと型定義
- テスト可能な設計

### 4. インポートパスの最適化

tsconfig.jsonでのパスエイリアス設定:

```json
{
  "paths": {
    "@/*": ["src/*"],
    "@components/*": ["src/components/*"],
    "@ui/*": ["src/components/ui/*"],
    "@lib/*": ["src/lib/*"]
  }
}
```

- 短く意味のある相対パス
- 一貫性のあるインポート規則
- モジュール間の依存関係の明確化

### 5. アプリケーションの状態管理

```
lib/store/      # 状態管理
├── auth.ts     # 認証状態
└── index.ts    # ストア設定
```

- 集中的な状態管理
- 型安全な実装
- テスト容易性の確保
